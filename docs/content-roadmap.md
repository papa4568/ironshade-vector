# Ironshade Vector — Active Production Roadmap

Only active/future executable work lives here. Completed and verified work belongs in [content-roadmap-archive.md](./content-roadmap-archive.md). Stable product rules live in [product-constraints.md](./product-constraints.md).

## Execution contract

- Execute top to bottom. The **first unchecked top-level item is next** unless the user explicitly changes priority.
- One checkbox should fit one realistic **implement → test → build → APK verification** cycle.
- Split an item before coding if it spans independent systems or verification cycles; combine tiny changes when they touch the same system and can be verified together.
- An item is complete only when its requested behavior works, relevant regression checks pass, the production build succeeds, and the Android deliverable is verified as required by the repository workflow.
- After verified completion, move the completion detail/evidence to the archive and remove the item from this file.
- If repository evidence shows an active item is already complete, verify that evidence before archiving it. If only part is complete, rewrite the item around the remaining work.

## P19 — Glance-First Adaptive UI

Preserve Ironshade's existing hard-sci-fi art direction, rarity language, panel treatment, class control scheme, accessibility foundation, progressive-disclosure primitives, and requirement-state system. This phase changes information priority and compact-phone composition rather than reskinning the game.

- [ ] **P19-D — Armory inventory cards become decision-first** — Simplify stored/equipped inventory cards so the default scan answers only: what the item is, rarity, slot, one defining effect, whether it is usable/equippable now, and a concise build-fit or current-vs-candidate delta. Reuse P18-E's inspector and shared Details sheet for recovery level, modifier grades, frame quality, Augment detail, provenance, registry metadata, and other expert information instead of repeating those layers on every card. Route durable equipment/rarity teaching into the P19-C Guide while retaining immediate equip/compare guidance locally. Preserve sorting/filtering, rarity cues, class-family restrictions, equip actions, and all underlying item data. **Done when:** representative phone inventory rows/cards can be scanned without 6–9px metadata stacks, the primary equip/compare signal is visible before inspection, blocked/active states remain explicit through the shared requirement presentation, every removed card detail remains reachable in the inspector/details flow, durable how-to links resolve to the Guide, gear/readability/menu regressions pass, the production build succeeds, and the Android debug APK passes storage/compare/equip and inspector/Guide drilldown smoke checks.

- [ ] **P19-E — Build management hierarchy + P18-F verification closure** — Recompose Progression, Skills, and Crafting around the same decision-first rule without replacing the P18 eligibility/disclosure implementation: keep the immediate choice, cost/tradeoff, ready/active/blocked state, blocker reason, and next requirement at the decision point; move durable instructional prose and system explanations into the P19-C Guide, while keeping genuinely decision-specific previews/math in the shared Details flow. Raise compact-phone decision and secondary text to the shared mobile floor rather than compressing dense panels. Treat the existing P18-F implementation as inherited work and close its missing standalone verification here instead of claiming it was already APK-verified. **Done when:** Progression, Skills, and Crafting remain fully actionable on representative compact landscape without decoding tiny copy, P18-F requirement-state and disclosure markers still pass, costs/warnings/blockers remain visible without opening help, durable “how it works” content resolves to canonical Guide sections, no decision-critical content is lost, UI/design-system/crafting/operator-network regressions pass, the production build succeeds, and the Android debug APK passes touch/controller navigation, requirement-state, Guide/deep-link, disclosure, and planner-persistence smoke checks.

- [ ] **P19-F — HUD layout presets + movable control clusters** — Add a small persisted combat-layout model rather than a large settings subsystem: Standard, Large, and Left-Handed presets plus bounded reposition/scale controls for the movement cluster and combat/action cluster. Keep mission-critical alerts/objective information fixed, preserve manual aim/assisted targeting semantics, constrain controls to safe areas and non-overlap bounds, and reuse normalized profile settings/save migration rather than creating a parallel preference store. Put durable control explanations in the P19-C Guide and keep only the settings/actions needed to configure the current layout on the settings surface. **Done when:** legacy profiles default safely, all three presets can be selected/reset and survive relaunch, movement and combat clusters can be repositioned/scaled without moving fixed mission-critical UI offscreen or overlapping each other, touch hit regions track the visible controls, Guide control references match the actual layouts, text-scale/high-contrast/reduced-motion behavior remains compatible, focused persistence/input regressions pass, the production build succeeds, and the Android debug APK verifies all presets plus customized layout across launch/resume/rotation.

- [ ] **P19-G — Compact-phone typography sweep + device acceptance** — Audit the remaining compact-phone UI outside the earlier batches, especially `menuOverhaul.css` and `readability.css`, and eliminate residual 6–9px user-facing labels by either promoting them to the shared mobile type floor or moving secondary material into the Guide/existing disclosure patterns. Preserve desktop/tablet density where it remains readable; do not solve fit by scaling the entire interface down. Capture representative before/after compact-landscape screenshots and use the finished APK for a 6–7 inch Android landscape pass covering combat, Command, Armory, Progression, Skills, Crafting, Ship, Intel, and Guide. **Done when:** targeted compact-phone surfaces have no user-facing 6–9px text declarations left as a fit workaround, critical/decision/secondary hierarchy remains visually distinct, migrated instructional content remains discoverable through Guide links, no horizontal overflow or safe-area regressions appear with default or Large text, final QA records readable text, thumb reach, playfield occlusion, and remaining eye-travel hotspots on a representative 6–7 inch Android device, the full production build succeeds, and the verified APK completes the established mobile/accessibility/runtime smoke suite.
