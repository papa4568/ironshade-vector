# Ironshade Vector — Active Production Roadmap

Only active/future executable work lives here. Completed and verified work belongs in [content-roadmap-archive.md](./content-roadmap-archive.md). Stable product rules live in [product-constraints.md](./product-constraints.md).

## Execution contract

- Execute top to bottom. The **first unchecked top-level item is next** unless the user explicitly changes priority.
- One checkbox should fit one realistic **implement → test → build → APK verification** cycle.
- Split an item before coding if it spans independent systems or verification cycles; combine tiny changes when they touch the same system and can be verified together.
- An item is complete only when its requested behavior works, relevant regression checks pass, the production build succeeds, and the Android deliverable is verified as required by the repository workflow.
- After verified completion, move the completion detail/evidence to the archive and remove the item from this file.
- If repository evidence shows an active item is already complete, verify that evidence before archiving it. If only part is complete, rewrite the item around the remaining work.

## P19 — Glance-First Adaptive UI

Preserve Ironshade's existing hard-sci-fi art direction, rarity language, panel treatment, class control scheme, accessibility foundation, progressive-disclosure primitives, and requirement-state system. This phase changes information priority and compact-phone composition rather than reskinning the game.

- [ ] **P19-A — Combat HUD information layers + mobile type floor** — Recompose the compact-phone combat HUD around three information layers instead of shrinking every existing surface: keep HP/armor/capacitor, the current objective, and the right-thumb action dock continuously visible; show target/boss, loot, interaction, optional-objective, and post-clear navigation only while relevant; and route short-lived warnings/tutorial/event/status messaging through one shared transient-alert lane. Move technical percentages, mutation explanations, and extended state descriptions out of the permanent HUD while preserving critical combat tells, assisted-target feedback, world cues, safe areas, and the existing touch-control scheme. Establish the compact-phone typography floor in the combat presentation: roughly 12px minimum for secondary labels, 14–16px for decision information, and larger critical numbers/actions; if content does not fit, disclose or recompose it instead of dropping to 6–9px. **Done when:** a representative compact landscape viewport presents vitals/objective/actions without competing permanent panels, contextual surfaces appear and clear with their real gameplay states, transient alerts no longer stack in independent lanes, no user-facing combat text relies on 6–9px sizing, touch targets and critical world/HUD cues remain usable, focused combat/readability/accessibility regressions pass, the production build succeeds, and the Android debug APK passes touch/controller combat plus HUD-overlap smoke checks.

- [ ] **P19-B — Adaptive five-item Command dock** — Keep the existing Command / Operations / Operator / Ship / Intel information architecture, but render it as a five-item bottom command dock on compact phone windows and retain the current rail/sidebar treatment for tablet, desktop, and genuinely wide layouts. Reuse the existing safe-area, focus, active-page, keyboard/controller, and touch semantics; do not fork destination logic. Size compact-phone labels and targets for glanceability/thumb reach rather than preserving the current narrow rail with tiny text. **Done when:** all five destinations remain reachable with identical routing/state semantics across compact and wide layouts, compact landscape uses a safe-area-aware bottom dock with readable labels and at least 48px-class touch targets, wider layouts keep the rail without regression, no horizontal content loss is introduced, menu/design-system/browser regressions pass, the production build succeeds, and the Android debug APK verifies touch/controller navigation, back behavior, rotation, and dock/rail breakpoint behavior.

- [ ] **P19-C — Armory inventory cards become decision-first** — Simplify stored/equipped inventory cards so the default scan answers only: what the item is, rarity, slot, one defining effect, whether it is usable/equippable now, and a concise build-fit or current-vs-candidate delta. Reuse P18-E's inspector and shared Details sheet for recovery level, modifier grades, frame quality, Augment detail, provenance, registry metadata, and other expert information instead of repeating those layers on every card. Preserve sorting/filtering, rarity cues, class-family restrictions, equip actions, and all underlying item data. **Done when:** representative phone inventory rows/cards can be scanned without 6–9px metadata stacks, the primary equip/compare signal is visible before inspection, blocked/active states remain explicit through the shared requirement presentation, every removed card detail remains reachable in the inspector/details flow, gear/readability/menu regressions pass, the production build succeeds, and the Android debug APK passes storage/compare/equip and inspector-drilldown smoke checks.

- [ ] **P19-D — Build management hierarchy + P18-F verification closure** — Recompose Progression, Skills, and Crafting around the same decision-first rule without replacing the P18 eligibility/disclosure implementation: keep the immediate choice, cost/tradeoff, ready/active/blocked state, blocker reason, and next requirement at the decision point; move instructional prose, formulas, technical math, and secondary system explanation into the shared Details / How it works flow. Raise compact-phone decision and secondary text to the shared mobile floor rather than compressing dense panels. Treat the existing P18-F implementation as inherited work and close its missing standalone verification here instead of claiming it was already APK-verified. **Done when:** Progression, Skills, and Crafting remain fully actionable on representative compact landscape without decoding tiny copy, P18-F requirement-state and disclosure markers still pass, costs/warnings/blockers remain visible without opening help, no decision-critical content is lost, UI/design-system/crafting/operator-network regressions pass, the production build succeeds, and the Android debug APK passes touch/controller navigation, requirement-state, disclosure, and planner-persistence smoke checks.

- [ ] **P19-E — HUD layout presets + movable control clusters** — Add a small persisted combat-layout model rather than a large settings subsystem: Standard, Large, and Left-Handed presets plus bounded reposition/scale controls for the movement cluster and combat/action cluster. Keep mission-critical alerts/objective information fixed, preserve manual aim/assisted targeting semantics, constrain controls to safe areas and non-overlap bounds, and reuse normalized profile settings/save migration rather than creating a parallel preference store. **Done when:** legacy profiles default safely, all three presets can be selected/reset and survive relaunch, movement and combat clusters can be repositioned/scaled without moving fixed mission-critical UI offscreen or overlapping each other, touch hit regions track the visible controls, text-scale/high-contrast/reduced-motion behavior remains compatible, focused persistence/input regressions pass, the production build succeeds, and the Android debug APK verifies all presets plus customized layout across launch/resume/rotation.

- [ ] **P19-F — Compact-phone typography sweep + device acceptance** — Audit the remaining compact-phone UI outside the earlier batches, especially `menuOverhaul.css` and `readability.css`, and eliminate residual 6–9px user-facing labels by either promoting them to the shared mobile type floor or moving secondary material behind the existing disclosure patterns. Preserve desktop/tablet density where it remains readable; do not solve fit by scaling the entire interface down. Capture representative before/after compact-landscape screenshots and use the finished APK for a 6–7 inch Android landscape pass covering combat, Command, Armory, Progression, Skills, Crafting, Ship, and Intel. **Done when:** targeted compact-phone surfaces have no user-facing 6–9px text declarations left as a fit workaround, critical/decision/secondary hierarchy remains visually distinct, no horizontal overflow or safe-area regressions appear with default or Large text, final QA records readable text, thumb reach, playfield occlusion, and remaining eye-travel hotspots on a representative 6–7 inch Android device, the full production build succeeds, and the verified APK completes the established mobile/accessibility/runtime smoke suite.
