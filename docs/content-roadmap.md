- Execute top to bottom. The **first unchecked top-level item is next** unless the user explicitly changes priority.

- [ ] **P20-D — Class-aware recommended build paths** — Add or reconcile a small authored set of recommended Operator Network paths using the verified P20-C mechanics and the existing planner instead of a generic optimizer. Recommendations must respect the locked class arsenals and explain the gameplay loop they strengthen: Vanguard recommendations should connect Breacher pressure/armor break/Guard, Vector recommendations should connect Rail precision/range/mobility/Slipstream, and Systems recommendations should connect Carbine capacitor/control/recovery/Closed Loop; selected specializations may refine those paths only when their milestones/unlocks apply. - [ ] **P20-E — Distinct gameplay identities for standard repeatable contracts** — Rework the standard non-story repeatable contract families so Salvage, Boarding, and Stabilization are recognizable mission types rather than interchangeable combinations of the shared objective pool. Build each family from reusable encounter/objective primitives but give it an authored primary loop, objective sequencing, encounter/director pressure, environmental fit, and safe-vs-deep risk pattern that remains identifiable while locations/conditions rotate. Preserve campaign/story contracts and the already-distinct Daily Operation, Escalation, Directive, and rare megastructure systems instead of flattening them into the new standard templates. **Done when:** deterministic multi-cycle generation shows all three standard families repeatedly produce legal but materially different mission flows, encounter/objective tests verify each family's authored mechanics and deep-risk identity, campaign/special-operation regressions remain unchanged, Browser E2E can distinguish the three choices from briefing/objective presentation before deployment, production build passes, and Android play smoke completes one representative contract of each family.

- [ ] **P20-F — Individual incentives for repeatable contract choices** — Give each standard repeatable contract family a clear pre-deployment reason to run it by differentiating its reward/chase profile using the existing economy, faction/reputation, gear-source, optional-objective, and recovery systems rather than adding redundant currencies by default. Surface the distinctive payoff on the contract card/briefing, keep safe/deep extraction tradeoffs meaningful, and tune the profiles so no single family is the strictly best answer for every progression need while each remains useful across repeated cycles. **Done when:** settlement/generation tests prove each family grants its authored incentive and cannot leak campaign-only rewards, a balance matrix across representative early/mid/late profiles shows distinct needs served by each family, UI clearly communicates the expected payoff before launch, Browser E2E + production build pass, and the verified APK confirms reward presentation and post-contract settlement for all three families.
