# Ironshade Vector — Active Production Roadmap

Only active/future executable work lives here. Completed and verified work belongs in [content-roadmap-archive.md](./content-roadmap-archive.md). Stable product rules live in [product-constraints.md](./product-constraints.md).

## Execution contract

- Execute top to bottom. The **first unchecked top-level item is next** unless the user explicitly changes priority.
- One checkbox should fit one realistic **implement → test → build → APK verification** cycle.
- Split an item before coding if it spans independent systems or verification cycles; combine tiny changes when they touch the same system and can be verified together.
- An item is complete only when its requested behavior works, relevant regression checks pass, the production build succeeds, and the Android deliverable is verified as required by the repository workflow.
- After verified completion, move the completion detail/evidence to the archive and remove the item from this file.
- If repository evidence shows an active item is already complete, verify that evidence before archiving it. If only part is complete, rewrite the item around the remaining work.

## P21 — Graphics Engine Modernization

- [ ] **P21-A — Isolate renderer seams and add a deterministic graphics comparison harness** — Refactor only the minimum boundaries around the existing Three.js combat renderer so renderer/backend selection, post-processing, lighting setup, and graphics diagnostics are not hard-wired into the monolithic `threeCombatRenderer.ts`. Add a non-production graphics-path selector plus a deterministic Asteroid Refinery showcase state that can be launched repeatedly without changing simulation, collision, targeting, controls, saves, React UI, or mission logic. Record baseline renderer metrics already available in-browser such as draw calls, triangles, frame timing, active adaptive tier, and loaded graphics path. **Done when:** the normal WebGL2 renderer still produces the existing game unchanged by default; the deterministic refinery showcase can be launched through the new comparison seam; targeted renderer tests cover path selection and baseline telemetry; Browser E2E and production build pass; and the Android APK passes the existing install/launch/touch/lifecycle graphics smoke with no gameplay regression.

- [ ] **P21-B — Upgrade Asteroid Refinery WebGL2 lighting and PBR material response** — Improve only the Asteroid Refinery vertical slice using the current WebGL2 path: add environment/IBL lighting or an equivalent scene-lighting probe, rebalance key/rim/practical lights, strengthen physically based metal/roughness response, and tune ACES exposure so authored machinery, operator, enemies, and floor materials gain readable depth without washing out combat cues. Do not add bloom/AO yet and do not change gameplay geometry. **Done when:** deterministic before/after captures show materially stronger form, surface, and depth separation in the refinery; authored assets remain readable at normal phone combat zoom; targeted graphics/material tests pass; Browser E2E and production build pass; and the verified Android APK renders the upgraded refinery without lifecycle/resource corruption.

- [ ] **P21-C — Add selective emissive bloom to the WebGL2 refinery slice** — Add a bounded post-processing stage for selective bloom on authored emissive/practical-light sources and important VFX only. Prevent bloom from affecting HUD/UI, flattening silhouettes, or obscuring enemy attacks, hazards, objectives, loot, and interactables. Give the effect an explicit runtime cost control so it can later be scaled by adaptive quality. **Done when:** bloom is visibly present on intended refinery lights/VFX but gameplay cues remain readable; non-emissive surfaces and UI do not bloom incorrectly; targeted post-processing tests pass; Browser E2E and production build pass; and Android APK verification confirms stable rendering through combat plus pause/resume.

- [ ] **P21-D — Add ambient/contact depth and refinery atmosphere** — Add one mobile-conscious ambient/contact-occlusion technique plus location-aware fog/atmosphere and restrained color treatment for the Asteroid Refinery WebGL2 path. Keep effects scene-only, deterministic where practical, and independent from simulation coordinates. Avoid stacking multiple expensive depth effects in the same batch. **Done when:** machinery intersections, floor contact, and foreground/background separation are visibly improved without muddying combat readability; the effect can be disabled cleanly; targeted graphics regressions pass; Browser E2E and production build pass; and the Android APK completes refinery combat and lifecycle smoke without visual/resource faults.

- [ ] **P21-E — Integrate the new WebGL2 effects with adaptive quality budgets** — Wire upgraded lighting, bloom, ambient/contact depth, fog detail, shadow resolution/casters, reflections, and secondary VFX into the existing High/Balanced/Performance render tiers. Preserve gameplay-critical cues at full strength while reducing secondary graphics cost in lower tiers. Add explicit light/shadow/post-processing budgets rather than relying on incidental scene complexity. **Done when:** deterministic quality tests prove High, Balanced, and Performance materially reduce secondary rendering cost in order while preserving gameplay cues; sustained frame-pressure simulation still downgrades and recovers correctly; Browser E2E and production build pass; and Android APK verification confirms all three tiers remain playable and visually coherent.

- [ ] **P21-F — Build an isolated WebGPU/TSL Asteroid Refinery prototype** — Add a non-production Three.js WebGPURenderer/TSL path for the same deterministic refinery showcase, using WebGL2 fallback where the platform requires it. Reuse the existing GLB/KTX2/Meshopt asset pipeline and reproduce only the already-proven P21-B–E visual treatment needed for comparison; do not port the whole game or make WebGPU the production default. Record unsupported materials/effects, fallback behavior, bundle delta, renderer initialization differences, and Android WebView compatibility. **Done when:** the deterministic refinery showcase can switch between upgraded WebGL2 and WebGPU/TSL comparison paths without changing gameplay state; targeted backend-selection tests pass; Browser E2E and production build pass; and the Android APK either successfully exercises the prototype/fallback path or records a reproducible platform limitation without breaking the production WebGL2 path.

- [ ] **P21-G — Make the engine decision from measured refinery evidence** — Compare the verified WebGL2 and WebGPU/TSL slices using the existing graphics diagnostics plus captured screenshots: visual result, draw calls/triangles, frame-time behavior, adaptive-tier behavior, bundle/APK impact, Android compatibility, implementation complexity, and renderer-specific defects. In the same batch, document the concrete systems that a future Godot/Unity-class full replatform would have to replace or bridge: TypeScript simulation, React UI, Capacitor Android integration, deterministic test harnesses, save/runtime contracts, graphics asset loading, and release QA. Record a single next-path decision in a graphics engine decision document and update the roadmap so only work for that chosen path follows; do not begin a full replatform in this task. **Done when:** the comparison evidence and engine decision are committed, the active roadmap is reordered around the selected path, no speculative migration tasks remain ahead of that decision, Browser E2E and production build still pass, and the current production Android APK is reverified after the roadmap/decision changes.

## P20 — Build Usability, Skill Integrity & Repeatable Contract Identity

- [ ] **P20-E — Distinct gameplay identities for standard repeatable contracts** — Rework the standard non-story repeatable contract families so Salvage, Boarding, and Stabilization are recognizable mission types rather than interchangeable combinations of the shared objective pool. Build each family from reusable encounter/objective primitives but give it an authored primary loop, objective sequencing, encounter/director pressure, environmental fit, and safe-vs-deep risk pattern that remains identifiable while locations/conditions rotate. Preserve campaign/story contracts and the already-distinct Daily Operation, Escalation, Directive, and rare megastructure systems instead of flattening them into the new standard templates. **Done when:** deterministic multi-cycle generation shows all three standard families repeatedly produce legal but materially different mission flows, encounter/objective tests verify each family's authored mechanics and deep-risk identity, campaign/special-operation regressions remain unchanged, Browser E2E can distinguish the three choices from briefing/objective presentation before deployment, production build passes, and Android play smoke completes one representative contract of each family.

- [ ] **P20-F — Individual incentives for repeatable contract choices** — Give each standard repeatable contract family a clear pre-deployment reason to run it by differentiating its reward/chase profile using the existing economy, faction/reputation, gear-source, optional-objective, and recovery systems rather than adding redundant currencies by default. Surface the distinctive payoff on the contract card/briefing, keep safe/deep extraction tradeoffs meaningful, and tune the profiles so no single family is the strictly best answer for every progression need while each remains useful across repeated cycles. **Done when:** settlement/generation tests prove each family grants its authored incentive and cannot leak campaign-only rewards, a balance matrix across representative early/mid/late profiles shows distinct needs served by each family, UI clearly communicates the expected payoff before launch, Browser E2E + production build pass, and the verified APK confirms reward presentation and post-contract settlement for all three families.
